than the numbering suggests.

the document is wrong and should be fixed. Two of these are enforced by
`test/docs.test.js`, and one has its numbers generated by a script.

## The documents that are tested, and the one that is generated

`test/docs.test.js` asserts:

- every field in `newState()` is documented in `01`, and nothing in `01` names
  a field that no longer exists;
- every dial, gauge, scenario, shock and ending is named in `01`, `09` or `10`;
- every lag-pipeline target has a player-facing name, so the pipeline panel
  cannot render a raw field name;
- every file in this directory is listed above.

And `11-cause-and-effect.md` does not need a test, because every number in it
is printed by `node tools/cause-effect.mjs`. Re-run it after touching a rule
and paste the output back in — a hand-written claim about what a model does,
written by reading the model, is how `07` came to exist.

That exists because `01` went badly stale without anyone noticing — it listed
`transfers` as a player dial when it is automatic, gave a `neutral_rate` of
3.0% when the model has a `neutral_real_rate` of 0.5%, and documented two
variables that had been deleted. A design document that quietly stops matching
the code is worse than no design document, because people still trust it.

## Generated results

`TEST-RESULTS.md` in the repo root is the whole measured behaviour of the model
in one file: every test with its status, the **full text of all eleven recorded
disagreements with published evidence** and the number each one measured, and
the regenerated cause-and-effect tables. Written to be readable cold.

    npm run report        regenerates it (~2s)

It reports the failures and disagreements in full, deliberately. A results file
that only showed the passing parts would be marketing.

## The standing rules these documents keep restating

They are restated because each one has already been broken at least once.

1. **`parameters.py` is the record.** Every coefficient carries its range, how
   good the evidence is, and where it came from.
2. **Never average away a real dispute.** Mark it `contested`, give both camps,
   code one as default and say which.
3. **Never tune to a dramatic target.** Where the model disagrees with the
   literature, that is a finding to surface, not a coefficient to move. Eleven
   disagreements are currently recorded as failing-by-design `todo` tests.
   Related, and the trap underneath two of them: **a reduced form is not a
   structural input.** A published peak-to-trough fall already contains the
   multiplier; feeding it in as a shock and letting the model multiply it again
   is decision A3's error wearing a different hat.
4. **No rule may modify state without recording why.** `trace.record` throws if
   the terms do not sum to the total.
5. **The steady state must hold.** 200 ticks of no input, zero drift.
6. **A regime has to be DRIVEN, not asserted.** Setting `unemployment: 9` does
   nothing; the labour rule pulls it back within months. Three of six scenarios
   had to be rebuilt for breaking this.
7. **State dependence is checked with two measurements, never one.** Every
   defect the audit found was a statement about how a response *changes* with
   the state, and every one passed a suite that checked levels.
8. **The dial is not the stance, and no rule may read the slider.** A rule that
   branches on `s.policy_rate` hands the player an instantaneous change in the
   structure of the economy, in a model whose whole thesis is that nothing is
   instant. Two did, both inverted a lesson, and `tools/lint.mjs` now enforces
   it with declared exceptions (docs/12 L3, L5).
9. **Measure the response on the timescale the mechanism works on.** Two
   findings in `docs/12` were my own measurements being wrong, not the model:
   compounding a one-tick derivative over 96 months after the feedback had been
   given a seven-year lag, and reading a stance mid-flight through a lag kernel
   and calling it a ratchet.
